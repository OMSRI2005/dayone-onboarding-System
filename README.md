# DayOne Onboarding — Frontend

A responsive two-view employee onboarding frontend for the internship project. Built with HTML, CSS and vanilla JavaScript so it can be hosted as static files on Amazon S3 and delivered through CloudFront.

## What's included

- `index.html` — sign-in entry screen and safe preview navigation
- `onboarding.html` — new-hire portal with stage progress, document selection, policy acknowledgement
- `admin.html` — HR pipeline dashboard, search, filters, employee details modal, stage summary and CSV export
- `css/styles.css` — responsive design system and components
- `js/config.js` — configuration switches and file validation limits
- `js/api.js` — shared API client with demo data and placeholder API contracts
- `js/auth.js`, `js/onboarding.js`, `js/admin.js` — page logic

## Run locally

1. Unzip the project.
2. Open the folder in VS Code.
3. Use the Live Server extension, or run a local static server:

   ```bash
   python3 -m http.server 5500
   ```

4. Open `http://localhost:5500` in your browser.

You can also open `index.html` directly, but using a local server is more representative of hosting.

## Preview mode

The project starts with `USE_MOCK_DATA: true`. Use the **Preview new hire portal** or **Preview HR dashboard** buttons to explore the UI. The employee and activity records are synthetic sample data.

**Preview mode does not authenticate with Cognito, upload files to S3, send email, or write to DynamoDB.** The document picker validates file type and size in the browser, but deliberately does not upload selected files.

## Connect the team's APIs

Edit `js/config.js` after the backend team shares deployed endpoint details:

```js
window.DAYONE_CONFIG = {
  API_BASE_URL: "https://YOUR_API_ID.execute-api.ap-south-1.amazonaws.com/prod",
  USE_MOCK_DATA: false,
  MAX_FILE_SIZE_BYTES: 10 * 1024 * 1024,
  ALLOWED_FILE_TYPES: ["application/pdf", "image/jpeg", "image/png"],
  CONTACT_EMAIL: "hr@example.com"
};
```

This only enables the API client. It does **not** automatically implement Cognito authentication. Integrate Cognito sign-in using the approach agreed with Person 1 and pass a valid access/ID token to the API client. Do not store long-lived secrets in browser code.

### Proposed endpoint contract — confirm with teammates

| Method | Path | Used for |
|---|---|---|
| `GET` | `/employees` | HR employee list |
| `GET` | `/employees/{employee_id}/progress` | Employee stage progress |
| `POST` | `/employees/{employee_id}/stages/{stage_id}/complete` | Submit stage completion |
| `POST` | `/employees/{employee_id}/documents/upload-url` | Request short-lived S3 upload URL |
| `POST` | `/employees/{employee_id}/documents/complete` | Register uploaded document |

The exact paths, request/response properties, CORS configuration and authorization rules must match the deployed APIs. These are integration placeholders, not claims that the backend exists yet.

Expected upload URL response example:

```json
{
  "upload_url": "https://short-lived-presigned-url",
  "object_key": "private/employee-id/document-id",
  "document_id": "document-id"
}
```

## Before production

- Replace demo preview navigation with Cognito authentication.
- Enforce HR-only access in the backend; hiding UI is not authorization.
- Confirm API Gateway CORS allows only the deployed frontend origin.
- Keep document storage private and use S3 presigned URLs.
- Add server-side file validation, malware scanning if required, and document verification.
- Do not trust browser-side validation as a security boundary.
- Add loading, retry, expired-session and network-error states.
- Use real backend stage status as the source of truth for Day 1 readiness.
- Never commit AWS access keys, credentials, real employee documents or tokens.
- Review keyboard accessibility and test on mobile/desktop browsers.

## Deploy static frontend to S3

1. Create a dedicated S3 bucket for the frontend.
2. Upload the frontend files and enable static hosting only if using that hosting pattern.
3. Prefer CloudFront with HTTPS for a production-like demo.
4. Keep the separate document bucket private; do not reuse a public frontend bucket for employee documents.
5. Set the frontend API URL to the correct API Gateway base URL.
6. Verify CORS, Cognito callback URLs and authorization against the deployed domain.

## Known limitations

- The current login form is a UI prototype; Cognito authentication is not wired up.
- Dashboard records are sample data until the live API is configured.
- File selection performs client-side checks only in preview mode; no file is sent anywhere.
- HR document review/approve/reject controls require backend endpoints and are not implemented as fake approvals.
- Reminder emails and workflow automation run in AWS, not in frontend JavaScript.
